# Mode 06: проверенные масштабы для захвата CT200h

16 ноября 2026 года. Исследование без аппаратных вызовов и изменения основного кода. Проверен уже сохранённый первичный захват `outputs/live-expanded-mcp-page2-2026-11-16.json`: ECU `7E8`, девять MID, семнадцать записей, пять различных UASID.

## Пять codecs

Первичная открытая реализация: [Shiny UnitAndScaling.cs](https://github.com/shinyorg/obd/blob/0352328690724e220702f43be0b036e33e2aa38c/src/Shiny.Obd/Commands/UnitAndScaling.cs), commit `0352328690724e220702f43be0b036e33e2aa38c`, [MIT](https://github.com/shinyorg/obd/blob/0352328690724e220702f43be0b036e33e2aa38c/LICENSE). Ниже факты формата для самостоятельной реализации; GPL-код не использовался.

| UASID | Исходное 16-битное значение | Масштаб | Offset | Единица |
|---|---|---:|---:|---|
| `0B` | unsigned | `0.001` | 0 | V |
| `8D` | signed, two's complement | `0.00390625` | 0 | mA |
| `86` | signed, two's complement | `0.000305` | 0 | raw, без физической размерности |
| `17` | unsigned | `0.01` | 0 | kPa |
| `24` | unsigned | `1` | 0 | count |

Shiny называет `86` единицей `count`. Нормативный SAE J1979 APR2002, Table E57 называет его **Raw Value** без физической единицы; поэтому `raw` / `dimensionless` точнее и не предполагает проценты. Та же таблица определяет signed масштаб `0.000305`. Table E61 подтверждает signed ток `8D`, Table E11 — unsigned напряжение `0B`. [Оригинальный SAE-документ в публичном архиве нормативных актов](https://law.resource.org/pub/us/cfr/ibr/005/sae.j1979.2002.pdf). Таблицы доступны в поисковом индексе; загруженный PDF является сканом и не дал извлекаемого текста.

Для каждого из `value`, `minimum`, `maximum` сначала собрать big-endian U16. Для signed codec преобразовать `u >= 32768` в `u - 65536`, затем применить `signed_or_unsigned * scale + offset`. Не округлять перед сравнением и не считать любое `FFFF` отсутствующим значением: для `8D` это −0.00390625 mA, для `86` −0.000305, для `24` 65535 count. Неизвестный UASID оставляет нормализованные поля и сравнение неизвестными.

## Семантика MID и TID

[Shiny MonitorIds.cs](https://github.com/shinyorg/obd/blob/0352328690724e220702f43be0b036e33e2aa38c/src/Shiny.Obd/Commands/MonitorIds.cs) подтверждает названия MID: `01` — O2 bank 1 sensor 1; `02` — O2 bank 1 sensor 2; `21` — catalyst bank 1; `31` — EGR bank 1; `A1` — общий misfire monitor; `A2..A5` — misfire cylinders 1..4.

Нормативная SAE J1979-DA OCT2011, Appendix C, Table C2 определяет TID `07` как минимальное, `08` как максимальное напряжение O2 за тестовый цикл; `0B` — EWMA misfire за предыдущие циклы, `0C` — misfire за последний/текущий цикл. Для `0B/0C` в этой таблице явно заданы MID `A2..AD` и UASID `24`. Диапазон TID `80..FE` производительский. [Оригинальный SAE PDF, публичная копия](https://f30.bimmerpost.com/forums/attachment.php?attachmentid=1800282&d=1523076762).

Поэтому пять фактически встреченных производительских комбинаций `01/8E`, `01/91`, `02/8F`, `21/A9`, `31/BD` сохраняем с hex TID. Их масштаб из UASID известен; точное название теста именно CT2013 не доказано. Найдены похожие Toyota-документы для других двигателей/лет с отличающимися определениями; автоматически переносить их нельзя. Для `07/08` использовать переданный ECU UASID `0B`, а не подменять его типовым `0A` из общей таблицы.

`A1/0B` и `A1/0C` в захвате есть, но приведённая нормативная таблица не определяет эти TID для `A1`. Общий MID можно назвать misfire monitor, а расширенную интерпретацию «все цилиндры, EWMA/last-current» пометить `unverified` до CT2013 OEM-источника. По соседним Toyota это правдоподобно, но не подтверждено для данной калибровки.

## Нормализованные результаты собственного raw replay

Это расчёт из сохранённых байтов автомобиля, а не новый опрос. Все семь не-счётчиков находятся внутри переданных ECU числовых границ. Это утверждение о сравнении чисел конкретного теста, не заключение о состоянии всего автомобиля.

| MID/TID | UASID | Значение | Минимум | Максимум | Единица |
|---|---|---:|---:|---:|---|
| `01/8E` | `0B` | 0.699 | 0.169 | 19.898 | V |
| `01/91` | `8D` | 1.47265625 | 0.703125 | 2.18359375 | mA |
| `02/07` | `0B` | 0.117 | 0 | 0.214 | V |
| `02/08` | `0B` | 0.761 | 0.585 | 0.995 | V |
| `02/8F` | `86` | 0.15982 | 0 | 2.0984 | raw |
| `21/A9` | `86` | 0.235765 | 0.2196 | 9.993935 | raw |
| `31/BD` | `17` | 14.41 | 0.74 | 655.35 | kPa |
| `A1..A5/0B,0C` | `24` | 0 у всех 10 записей | 0 | 65535 | count |

Для `A2..A5/0B,0C` нельзя выводить диагностический `passed=true` из попадания в `0..65535`: SAE J1979 MAY2007, p.91 объясняет, что для этих накопителей границы намеренно равны полному диапазону, поэтому накопители не дают fail. `within_reported_limits=true` допустимо как арифметический факт, `passed=null` — как диагностический результат. То же консервативное правило подходит встреченным `A1/0B,0C` с теми же границами. [Оригинальный SAE-документ, индексируемая публичная копия](https://www.autonerdz.com/yabbfiles/Attachments/1979v3.pdf); прямое открытие в момент проверки перенаправлялось на главную, текст p.91 прочитан через поисковый индекс.

Официальный OEM-источник независимо подтверждает стандартные названия `A2..AD/0B,0C`: [Ford 2010 HEV OBD System Operation Summary, p.17](https://www.fordservicecontent.com/ford_content/catalog/motorcraft/OBDSM1001_HEV.pdf). Это первичный источник стандартной семантики, а не подтверждение Toyota-калибровки.

## Проверки для самостоятельного декодера

В [Shiny Mode06Tests.cs](https://github.com/shinyorg/obd/blob/0352328690724e220702f43be0b036e33e2aa38c/tests/Shiny.Obd.Tests/Mode06Tests.cs) есть MIT-примеры signed `8C`, неизвестного UASID, формата/длины и нескольких записей. Это тесты библиотеки, не реальные CT200h capture; полного набора edge tests для наших пяти UASID там нет.

Минимальные собственные синтетические edge vectors из подтверждённых масштабов:

| UASID/raw | Ожидаемый результат |
|---|---|
| `0B/0001`, `0B/FFFF` | 0.001 V; 65.535 V |
| `8D/8000`, `8D/FFFF`, `8D/0100`, `8D/7FFF` | −128 mA; −0.00390625 mA; 1 mA; 127.99609375 mA |
| `86/8000`, `86/FFFF`, `86/7FFF` | −9.99424; −0.000305; 9.993935 |
| `17/3039` | 123.45 kPa |
| `24/FFFF` | 65535 count |

К ним добавить сохранённые 17 собственных записей, проверку одинакового преобразования value/min/max, неизвестный UASID, отрицательные пределы, неверный размер записи, конфликт MID, `minimum > maximum`, а также отдельную проверку `passed=null` для misfire-счётчиков. Не выводить «срок до отказа» из близости к границе.
